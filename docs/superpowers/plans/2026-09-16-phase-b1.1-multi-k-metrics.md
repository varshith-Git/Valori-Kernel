**Goal:** Extend `benchmarks/live_local_db_comparison.py` so one SciFact run over the HTTP path reports Recall@3/5/10, nDCG@3/5/10, MRR@10, complete_context@10, and latency mean/p50/p95/p99 for both the vector-only arm and the oracle-graph GraphRAG arm, writes to a new frozen results file without touching the original B1 result, and records reproducibility metadata — then actually run it and document it as Phase B1.1.

**Architecture:** No new files, no new architecture. One existing script (`benchmarks/live_local_db_comparison.py`) gets its `metrics()` function rewritten to compute multiple cutoffs, gains a `latency_stats()` helper for percentile timing, gains a `validate_ab()` sanity-check function, and `main()` gains a `--out` flag plus `meta`/`ingestion` output blocks. All three call sites of `metrics()` (FAISS, embedded-FFI, HTTP) are updated for the new signature; only the HTTP path gets full per-query latency instrumentation, since that's the only arm actually exercised for the recorded B1.1 run.

**Tech Stack:** Python 3, numpy, requests (already used by the script); pytest for the two pure-function unit tests (pytest 9.0.2 already installed; `benchmarks/test_snapshot_size.py` is this directory's existing precedent for a standalone `test_*.py` file, though that one predates assertion-based testing — this plan uses real `assert`-based pytest tests, which pytest will also auto-discover).

## Global Constraints

- Do not touch `crates/` — this is a benchmark-script-only change (per spec: "This is a benchmark-script change, not a Rust/kernel change").
- Do not overwrite `benchmarks/LIVE_LOCAL_RESULTS.json` (the B1 result). The B1.1 run writes to `benchmarks/LIVE_LOCAL_RESULTS_B1_1.json` via a new `--out` flag.

- No GraphRAG parameter tuning based on results. Once B1.1's JSON is written, it's frozen.
- Every changed line should trace to the spec at `docs/superpowers/specs/2026-09-16-phase-b1.1-multi-k-metrics-design.md`.

```python
def metrics(results, qrels, ks=(3, 5, 10)):
    """results[q] must already be ranked and truncated to at least max(ks) items."""
    max_k = max(ks)
    recall = {k: [] for k in ks}
    ndcg = {k: [] for k in ks}
    mrr, complete = [], []
    for q in results:
        goldmap = qrels[q]
        gold = {d for d, s in goldmap.items() if s > 0}
        got = results.get(q, [])[:max_k]
        for k in ks:
            got_k = got[:k]
            recall[k].append(len(set(got_k) & gold) / max(1, len(gold)))
            dcg = sum(1 / np.log2(i + 2) for i, d in enumerate(got_k) if d in gold)
            ideal = sum(1 / np.log2(i + 2) for i in range(min(k, len(gold))))
            ndcg[k].append(dcg / ideal if ideal else 0)
        rr = 0.0
        for i, d in enumerate(got):
            if d in gold:
                rr = 1 / (i + 1)
                break
        mrr.append(rr)
        complete.append(set(gold).issubset(set(got)))
    out = {}
    for k in ks:
        out[f"recall_at_{k}"] = round(float(np.mean(recall[k])), 4)
        out[f"ndcg_at_{k}"] = round(float(np.mean(ndcg[k])), 4)
    out["mrr_at_10"] = round(float(np.mean(mrr)), 4)
    out["complete_context"] = round(float(np.mean(complete)), 4)
    out["query_count"] = len(results)
    return out
```

```python
def validate_ab(out):
    """Data/math sanity checks only. Deliberately does NOT assert that the
    graph arm outperforms the vector arm -- a regression there is a valid
    experimental result, not a benchmark failure. Also deliberately does NOT
    assert any ordering across ndcg_at_3/5/10 -- nDCG's ideal-DCG denominator
    changes with the cutoff, so a correct implementation is not guaranteed to
    be monotonic in k (e.g. ndcg_at_3=0.91, ndcg_at_5=0.87, ndcg_at_10=0.89
    is legitimate)."""
    for name, m in out.get("systems", {}).items():
        if not isinstance(m, dict) or "recall_at_10" not in m:
            continue
        assert 0.0 <= m["recall_at_3"] <= m["recall_at_5"] <= m["recall_at_10"] <= 1.0, \
            f"{name}: recall_at_k not monotonic/in-range"
        assert 0.0 <= m["ndcg_at_3"] <= 1.0, f"{name}: ndcg_at_3 out of range"
        assert 0.0 <= m["ndcg_at_5"] <= 1.0, f"{name}: ndcg_at_5 out of range"
        assert 0.0 <= m["ndcg_at_10"] <= 1.0, f"{name}: ndcg_at_10 out of range"
        assert 0.0 <= m["mrr_at_10"] <= 1.0, f"{name}: mrr_at_10 out of range"
        assert 0.0 <= m["complete_context"] <= 1.0, f"{name}: complete_context out of range"
        assert m["latency_p99_ms"] >= m["latency_p95_ms"] >= m["latency_p50_ms"] >= 0.0, \
            f"{name}: latency percentiles not ordered"
        if "queries" in out:
            assert m["query_count"] == out["queries"], f"{name}: query_count does not match dataset query count"
```
